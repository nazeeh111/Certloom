What the checker proves

A certificate stores a square real system A x* = b and a proposed answer x. Sparse certificates supply positive weights; dense certificates supply an approximate inverse. The exact represented binary64 values define the mathematical problem. Both checkers recompute the proof with integer arithmetic, independently of the producing solver.

Sparse proof: weighted diagonal dominance

For every row i, compute the gap dᵢ = |aᵢᵢ| wᵢ − Σ(j ≠ i) |aᵢⱼ| wⱼ. Every weight and every gap must be strictly positive. Then compute the residual r = b − Ax and τ = maxᵢ |rᵢ| / dᵢ. Each exact component lies in [xᵢ − wᵢτ, xᵢ + wᵢτ]. Weights, gaps and residuals are not trusted assertions: the checker validates the weights and recomputes the rest.

To see why, let e be any vector and choose k maximizing |eₖ|/wₖ = M. The triangle inequality gives |(Ae)ₖ| ≥ M dₖ. A nonzero nullvector would contradict dₖ > 0, so A is invertible. Apply the same inequality to e = x* − x: M ≤ |rₖ|/dₖ ≤ τ, giving every stated component bound. Symmetry, positive definiteness and a common diagonal sign are unnecessary.

This is an established sufficient condition, not a general sparse solver. A zero or negative gap returns not_certified; failed supplied weights do not establish singularity or an incorrect answer. Finding useful weights is producer work. A common positive rescaling of all weights leaves the final radii unchanged. Checking traverses rows and nonzeros without expanding a dense matrix. Its arithmetic-operation count is linear in their number; exact integer bit sizes also affect cost.

Sparse input contract

The root object contains exactly format, A, b, x, weights and decision. The format is certloom-sparse-dd-v1. The matrix A contains exactly dimension, indptr, indices and data.

CSR, compressed sparse row storage, keeps the nonzero entries of each row together. Entry k has column indices[k] and value data[k]. Row i occupies entries from indptr[i] up to, but excluding, indptr[i + 1].

  • Dimension n is an integer from 1 to 4,096. At most 32,768 nonzeros are accepted. Index values must be integers, never booleans or floating-point values.
  • indptr has n + 1 entries, starts at zero, never decreases and ends at the number of nonzeros. indices and data have that matching length.
  • Columns are in [0, n) and strictly increasing within each row. Duplicate coordinates, unsorted rows and explicit zero entries refuse; there is no silent sorting or aggregation.
  • Missing entries mean exact zero. An empty row or missing diagonal is valid sparse data, but cannot satisfy the proof premise.
  • b, x and weights each have n entries. Every weight must be strictly positive.
  • Matrix data, vector entries and a decision threshold are canonical finite Python float.hex() strings. For example, one is 0x1.0000000000000p+0. The data are exact binary64 values, not arbitrary hexadecimal expressions or intended exact decimals.
  • decision is null or contains exactly index and above. The index is an integer in [0, n); the threshold uses the same canonical encoding.

The producer API is make_sparse_certificate(indptr, indices, data, b, x, weights, decision=None) in certloom.producer. It infers n from b and explicitly converts coefficients to finite binary64. It accepts integer arrays, including NumPy integer scalars, without a NumPy dependency. It performs no solver call, weight selection, sorting, duplicate aggregation, zero removal or dense expansion.

Exact result and threshold

Sparse results include status, dimension, method equal to weighted-diagonal-dominance, nonzeros and minimum_gap. A failed premise adds a reason and omits tau and enclosures. A certified result includes tau, one component radius in each entry of radii and lower/upper records in enclosures. These are not the dense mode's q, eta or common radius.

Each exact rational is an object with decimal-string numerator and positive denominator, reduced to lowest terms. These records are authoritative. Decimal endpoints round outward. For the strict request x*ᵢ > t, lower > t establishes above; upper ≤ t establishes not_above; otherwise the decision is undecidable. A certified enclosure can be too wide to establish a useful threshold.

The 400-cell FiPy handoff

The final transient and subsequent steady systems were captured from one execution of NIST's unchanged two-dimensional patched-boundary diffusion example. Each has 400 cells and 1,920 matrix nonzeros. FiPy 4.0.3 produced the systems with NumPy 2.3.5 and SciPy 1.18.1; both original corner checks passed. All 400 enclosures were independently checked using exact fractions. The bottom-right corner enclosures lie within [0.99, 1.01] and establish the separate threshold above 0.98.

The transient case uses unit weights. The steady case uses positive weights from one comparison-matrix solve. Replacing them with unit weights gives a zero minimum gap and a refused proof; altering the candidate corner to zero loses the threshold decision. These are labeled controls, not repaired application results.

The standalone checker and browser need none of the producer's numerical libraries. The certificate proves only the stored linear system. In particular, the final transient right-hand side contains a previous approximate state: this does not bound accumulated time-stepping error, PDE discretization error or physical-model error.

The original source is pinned to NIST FiPy commit d8f038a. The accompanying provenance, unchanged source, terms and attribution describe the capture and preserve NIST's notices. No large-scale performance or outside adoption claim follows from this example.

Dense proof remains supported

The certloom-linear-v1 root contains exactly format, A, R, b, x and decision. A and R are n-by-n arrays, b and x are length n, and n is from 1 to 128. The same canonical coefficient and decision rules apply. The producer API remains make_certificate(A, b, x, R, decision=None).

Let C = I − RA and q be its largest absolute row sum. If q < 1, the Neumann series makes RA invertible, so both square matrices R and A are invertible. For the unique exact solution x*, (I − C)(x* − x) = R(b − Ax). With η the largest absolute component of R(b − Ax), the common component radius is η / (1 − q). When q ≥ 1, the method returns not_certified without an enclosure.

The original 64-node ideal ladder, Hilbert examples and controls remain available. The ladder has 1-ohm neighboring links, grounded ends and a 1 A injection at node 32; an analytic solution checks all enclosures. This is a declared ideal circuit, not an electrical measurement. Dense checking retains its cubic worst-case work.

Representation, limits and trust

Inputs are data-only UTF-8 JSON at most 2 MiB. Duplicate keys, extra fields, nonfinite or noncanonical coefficients, unsupported structures and expressions refuse. Uploaded code is never executed. The browser parser also bounds structure to 100,000 nodes and depth 8. A disposable Web Worker provides Cancel and a 20-second deadline; input changes revoke old claims and exports. The standalone command has no browser worker deadline.

Both modes certify exact represented equations, not coefficient uncertainty, intended decimals, measurements, source authenticity or solver execution. Python and JavaScript independently implement the exact calculation. The detached Python checker includes source and recomputes from input rather than trusting an exported receipt. Bundles retain the NIST attribution and terms in NOTICES.txt, separately from Certloom's MIT license. This is executable numerical verification, not a formal proof-assistant certificate. Inspect and trust the implementation accordingly. Source and input hashes identify bytes, not a trusted author.

Established foundations

Weighted diagonal dominance and inverse-contraction bounds are established numerical verification theory. INTLAB 14.1 already provides broader sparse verified solves. FLINT/Arb provides rigorous ball arithmetic with adjustable precision and uncertain inputs. IntervalLinearAlgebra.jl is another established environment. Certloom focuses on the source-bearing result artifact that a recipient can check without the producing solver; it does not invent these bounds or replace broader methods.
